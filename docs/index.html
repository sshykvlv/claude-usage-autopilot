Why pace, not usage

37% used means nothing by itself. 37% on day one is an emergency; 37% on day six is comfortable. The autopilot compares the fraction of budget burned against the fraction of the week elapsed and turns it into a verdict:

BandWhat happens
OK / WATCHon track — nothing shown, nothing done
SELECTIVEburning fast — your sessions are advised to conserve & delegate
CONSERVATIONwon't make the reset — eco-mode engages automatically

What it does

📟 Statusline

h6% w32% — 5-hour and weekly usage always visible, color is the verdict. 10 characters, quarter-screen friendly.

🔻 Autonomous eco-mode

When the pace says you won't make the reset, new sessions switch to a cheaper model — and switch back after the weekly reset. Guarded, reversible, notified.

🧭 In-session alerts

Your Claude sessions get told when the budget is red, auth broke, or monitoring went stale — so the model itself starts conserving.

📈 Burn history

One line every 30 minutes. cua history shows the trend that explains where your week went.

⚙️ Grind detector

Dozens of edits on an expensive model? One polite suggestion to downshift — plus a GRIND token in the statusline.

🔌 Codex too

Optionally tracks OpenAI Codex CLI accounts next to Claude, from local telemetry.

Install

macOS · Claude Code · jq

git clone https://github.com/sshykvlv/claude-usage-autopilot.git cd claude-usage-autopilot && ./install.sh

No API keys, no accounts, no telemetry: it reads your own usage percentages via your existing Claude Code login and keeps everything in local files. Uninstall reverts every change: cua uninstall.

Not affiliated with Anthropic. "Claude" is used descriptively; the usage endpoint is the same one the Claude Code UI uses and may change.

Safety model

Automatically editing someone's model config is dangerous, so every transition is guarded: a flip never happens on a single reading, your manual edits always win over the automation (checksum-verified), racing with /model is detected, and stale data never triggers anything. Each guard exists because it caught a real failure during development.
